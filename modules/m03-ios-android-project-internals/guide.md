Learn this first — **app identity** (tasks.md Setup item 2). The *bundle ID* (iOS) or *application
ID / package* (Android) is the reverse-DNS key that uniquely identifies the app to the OS and the
stores; three environments need three different IDs or they collide. The *app name* is the label
under the icon. The *version number* (`version`, e.g. `1.0.0`) is the user-facing release, while the
*build number* (`ios.buildNumber` / `android.versionCode`) increments per build. *Icon* and *splash*
are image assets set in the app config; per-environment icons are what make the three installs
visually distinct. `app.config.js` is JavaScript rather than static `app.json`, so identity values
can be computed from an environment variable.

#### Step 6.2 — Create three distinct icon assets

**Goal:** produce the three icons the deliverable requires. The brief asks for a distinct icon per

This is a decision step: **default** = the generated placeholders below; **alternative** = branded

**Where:** your profile app repo root.

**Run:**

```bash
mkdir -p assets/icons
python3 - <<'PY'
import struct, zlib, pathlib

def chunk(tag, data):
    payload = tag + data
    return struct.pack(">I", len(data)) + payload + struct.pack(">I", zlib.crc32(payload) & 0xffffffff)

def solid_png(path, rgb):
    width = height = 1024
    raw = (b"\x00" + bytes(rgb) * width) * height
    png = b"\x89PNG\r\n\x1a\n"
    png += chunk(b"IHDR", struct.pack(">IIBBBBB", width, height, 8, 2, 0, 0, 0))
    png += chunk(b"IDAT", zlib.compress(raw))
    png += chunk(b"IEND", b"")
    pathlib.Path(path).write_bytes(png)

solid_png("assets/icons/icon-dev.png", (37, 99, 235))
solid_png("assets/icons/icon-staging.png", (217, 119, 6))
solid_png("assets/icons/icon-prod.png", (22, 101, 52))
PY
file assets/icons/icon-*.png
shasum assets/icons/icon-*.png
```

#### Step 6.3 — Write app.config.js with one identity per environment

**Goal:** replace static config with a function that varies name, icon, bundle ID/package and URL
scheme by environment — the core of "app identity through `app.config.js`".

**Where:** your profile app repo root.

**Run:** first substitute the three placeholders with the values you recorded in Step 6.1:
`<your-app-json-slug>` (the `slug`), `<your-app-json-bundle-identifier>` (the `ios.bundleIdentifier`,
also used to derive the Android package) and `<your-app-json-name>` (the `name`).

```bash
cat > app.config.js <<'EOF'
const SLUG = '<your-app-json-slug>';
const BASE_ID = '<your-app-json-bundle-identifier>';
const APP_NAME = '<your-app-json-name>';

const VARIANTS = {
  development: {
    name: `${APP_NAME} (Dev)`,
    bundleId: `${BASE_ID}.dev`,
    icon: './assets/icons/icon-dev.png',
    scheme: `${SLUG}-dev`,
  },
  preview: {
    name: `${APP_NAME} (Staging)`,
    bundleId: `${BASE_ID}.staging`,
    icon: './assets/icons/icon-staging.png',
    scheme: `${SLUG}-staging`,
  },
  production: {
    name: APP_NAME,
    bundleId: BASE_ID,
    icon: './assets/icons/icon-prod.png',
    scheme: SLUG,
  },
};

module.exports = ({ config }) => {
  const variant = VARIANTS[process.env.APP_VARIANT || 'production'];
  return {
    ...config,
    name: variant.name,
    slug: SLUG,
    version: '1.0.0',
    scheme: variant.scheme,
    ios: {
      ...config.ios,
      bundleIdentifier: variant.bundleId,
      buildNumber: '1',
      icon: variant.icon,
    },
    android: {
      ...config.android,
      package: variant.bundleId,
      versionCode: 1,
      icon: variant.icon,
      adaptiveIcon: {
        ...(config.android?.adaptiveIcon ?? {}),
        foregroundImage: variant.icon,
      },
    },
  };
};
EOF
```

#### Step 6.14 — Make a scratch copy for the prebuild skim

**Goal:** run `npx expo prebuild` without letting it regenerate or delete the committed native
folders — the README's "native folders stay committed, always" rule. This is a decision step:
**default** = a throwaway copy in `/tmp`; **alternative** = run prebuild in place; **change to the
alternative only if** you intentionally want to regenerate your committed native folders, which this
lab does not ask for.

**Where:** your profile app repo root.

**Run:**

```bash
mkdir -p /tmp/m03-prebuild
rsync -a --exclude node_modules --exclude ios --exclude android --exclude .git ./ /tmp/m03-prebuild/
ln -s "$(pwd)/node_modules" /tmp/m03-prebuild/node_modules
ls -a /tmp/m03-prebuild
```

**You should see:** the scratch directory contains `app.json`, `app.config.js`, `package.json`,
`assets/` and `notes/`, but **no** `ios/` or `android/`.

**Verify:** `ls -d /tmp/m03-prebuild/ios /tmp/m03-prebuild/android 2>/dev/null` prints nothing, and
`ls -ld /tmp/m03-prebuild/node_modules` shows a symlink to your project's pinned dependencies — this
makes Step 6.15 use the exact Expo version from M01/M02 rather than an `npx` download.

**If it fails:** `rsync: command not found` means it is unavailable — use
`cp -R ./ /tmp/m03-prebuild` and then delete `/tmp/m03-prebuild/ios`,
`/tmp/m03-prebuild/android`, `/tmp/m03-prebuild/node_modules` and `/tmp/m03-prebuild/.git`. If the
scratch copy already exists from a previous attempt, remove it first with
`rm -rf /tmp/m03-prebuild`. If `ln` reports the link already exists, remove it with
`rm /tmp/m03-prebuild/node_modules` and re-run the `ln` command.

**Capture:** none.

#### Step 6.15 — Run prebuild in the scratch copy

**Goal:** generate native folders you are allowed to read, so the last DoD item can be answered
without touching the real project.

**Where:** the scratch copy `/tmp/m03-prebuild`.

**Run:**

```bash
cd /tmp/m03-prebuild
npx expo prebuild --no-install
```

**You should see:** Expo generates `ios/` and `android/` in the scratch copy and prints the files it
created `[verify at cohort freeze]`. Adding `--no-install` skips CocoaPods/Gradle dependency
installation because you only need to read the files.

**Verify:** `ls -d /tmp/m03-prebuild/ios /tmp/m03-prebuild/android` lists both; then return to your
real project and run `git status --short` there — it must still show only your intended M03 changes,
not regenerated native folders.

**If it fails:** a prompt about overwriting existing folders means the scratch copy was not clean —
redo Step 6.14. A dependency error means you omitted `--no-install`; re-run with it.

**Capture:** the command output listing generated files.

#### Step 6.16 — Locate the bundle ID and version number in the native folders

**Goal:** answer the third DoD item by pointing at exact files and keys in the generated folders.

**Where:** the scratch copy `/tmp/m03-prebuild`.

**Run:** first find the iOS project folder name, then grep the four files. Replace `<App>` with the
folder name printed by `ls`.

```bash
ls /tmp/m03-prebuild/ios
grep -n 'CFBundleIdentifier\|CFBundleShortVersionString\|CFBundleVersion' /tmp/m03-prebuild/ios/<App>/Info.plist
grep -n 'PRODUCT_BUNDLE_IDENTIFIER' /tmp/m03-prebuild/ios/<App>.xcodeproj/project.pbxproj
grep -n 'applicationId\|versionCode\|versionName' /tmp/m03-prebuild/android/app/build.gradle
grep -n 'minSdkVersion\|compileSdkVersion\|targetSdkVersion' /tmp/m03-prebuild/android/build.gradle
```

**You should see:** `Info.plist` lines with `CFBundleIdentifier` (the bundle ID),
`CFBundleShortVersionString` (the user-facing version, `1.0.0`) and `CFBundleVersion` (the build
number, `1`); `project.pbxproj` lines with `PRODUCT_BUNDLE_IDENTIFIER`; `android/app/build.gradle`
lines with `applicationId`, `versionCode` and `versionName`; and `android/build.gradle` lines with
the three SDK levels you researched in Step 5.10.

**Verify:** you can name, without looking at this guide, the file that holds each value — that is
exactly what the Definition of done asks you to point to.

**If it fails:** `No such file or directory` for `<App>/Info.plist` means the placeholder still says
`<App>`; copy the real folder name from the `ls` output. If `CFBundleShortVersionString` is absent,
look for `CFBundleVersion` alone — some templates express the version there; note what you find
rather than inventing a key.

**Capture:** the four grep outputs plus a note listing each file path and the key it contains, in
`notes/m03-research.md`.

## 10. Pitfalls, logistics, and open items

- **Identity collisions** — the most likely failure. If two profiles share a bundle ID/package or
  name, the second install replaces the first. Steps 6.4 and 6.13 are the guards; the fix is to make
  the suffixes distinct and rebuild.
- **`app.config.js` vs `eas.json`** — identity *values* belong in `app.config.js`; `eas.json` picks
  which value set to use (`env.APP_VARIANT`) and controls build/distribution settings. Do not hand-
  edit native project files; that path is deferred to the capstone's Workshop D.
- **Prebuild vs committed native folders** — always inspect in the scratch copy (Step 6.14). The
  README's bare-workflow rule is that `ios/` and `android/` stay committed.
- **Missing assets** — three distinct icons are not supplied by the brief. Step 6.2 generates a local
  default; use cohort-branded assets instead if they exist `[confirm with trainer]`.
- **Accounts and credentials** — EAS free tier from M02 is required (Step 5.5); Apple Developer /
  Play Console credentials and a test device are needed for installable builds
  `[confirm with trainer]`. EAS Build builds iOS in the cloud, so a Mac pool is not a hard
  requirement.
- **Version freeze** — exact Node/Xcode point versions and EAS CLI flags must be re-verified against
  the cohort's pinned baseline `[verify at cohort freeze]`. No versions were invented here; the
  baseline is RN 0.88 / Expo SDK 58 / React 19.3.0 / Node 24 LTS / compileSdk 37 / targetSdk 36.
- **No planted faults** for M03, unlike M01 (three setup faults) and M02 (audit example row). Nothing
  needs a trainer-only reproduction script in this stage.
- **Out of scope, intentionally** — hand-edited Xcode schemes, Gradle flavors, a scene migration, an
  R8 fix, and EAS Update/OTA. They are not skipped steps; the brief resolves them out of this module.
